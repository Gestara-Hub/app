# Estrategia Frontend

## Decisao

O desenvolvimento deve comecar pelo frontend mockado antes da implementacao completa do backend.

## Contexto

O produto ainda precisa validar escopo, fluxos, telas, linguagem e regras operacionais. Construir a experiencia primeiro reduz o risco de modelar backend antes de entender a rotina real que a interface precisa suportar.

## Direcao

- Usar dados mockados realistas.
- Manter os mocks proximos de contratos futuros de API.
- Evitar espalhar dados soltos dentro de componentes.
- Criar uma camada de acesso a dados mockada que possa ser substituida por API real depois.
- Priorizar telas e fluxos do MVP de barbearia.

## Pendencias

- Analisar a arquitetura atual do frontend.
- Definir padrao de rotas.
- Definir padrao de estado.
- Definir organizacao de mocks.
- Definir biblioteca de calendario ou abordagem visual.
